### Two defects the R10 bed found that the verdicts could not see

1. **The candy could not build at all.** The install step was `command: install -Dm755 scripts/podcast-render "${HOME}/…"`. A `command:` step runs with CWD=`$HOME`, while the candy's own files are bound at `/ctx` — so the build died every time:

   ```
   install: cannot stat 'scripts/podcast-render': No such file or directory
   Error: building at STEP "RUN --mount=type=bind,from=podcast-audio,source=/,target=/ctx …": while running runtime: exit status 1
   charly: error: command "build": building podcast-audio-app: podman build failed: exit status 1
   ```

   That is why **no `charly` check had ever run against this candy**, and why the previous body's evidence was hand-run on the host. Fixed with the native verb the layer skill prescribes, which now emits:

   ```
   COPY --from=podcast-audio --chmod=0755 --chown=1000:1000 scripts/podcast-render /home/user/.local/share/podcast-audio/podcast-render
   ```

2. **The cast's voice labels never resolved.** The resolver handed the model's voice table to `awk` as a *filename* (`getline l < table`) instead of reading its content, so the lookup map was empty and every `--voice` override was labelled `sid-<N>`:

   ```
   {"name":"HOST_A","sid":9,"voice":"sid-9"}     <-- before
   {"name":"HOST_A","sid":9,"voice":"bm_george"} <-- after
   ```

   The check that owns this failed LOUDLY on the first bed run (`podcast-render-generic-cast … exit=1, want 0`) — exactly what a gate is for. Both fixes are in this commit.

### The cast, as the org's own fact

```
$ podcast-render --voice HOST_A=9 --voice HOST_B=7 --out ep guest.md
  "voices": [
    {"name":"CONCH","sid":1,"voice":"af_bella"},
    {"name":"TEMPER","sid":6,"voice":"am_michael"},
    {"name":"HOST_A","sid":9,"voice":"bm_george"},
    {"name":"HOST_B","sid":7,"voice":"bf_emma"}
```

The shipped default cast is the deliberate pair; any other name is mapped by `--voice` and labelled from the model's own `speaker2id` table, so an override is never mis-named.

### One measured platform constraint, recorded because it silently disarms checks

A `check:` step's fields resolve ONLY the auto-exports (`${HOME}`, `${USER}`, `${ARCH}`) — never a candy-declared variable. Naming one makes the step report **SKIPPED**, and a SKIP does not fail the run:

```
SKIP  check the Kokoro ONNX model is present  [plan:candy:kokoro-tts:1]  unresolved variables: KOKORO_MODEL
```

Measured 2026-10-08 on the producer PR, where six acceptances stopped asserting while the bed still printed PASS. This repo's `podcast-render-self-test` used to name `PODCAST_TTS_ENGINE`/`PODCAST_TTS_MODEL_DIR` and would have skipped the same way; it now lets the renderer fall back to its own env contract, which proves the same thing and cannot be silently skipped. The constraint is documented in `AGENTS.md` and in the candy.
